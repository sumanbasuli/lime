## Upgrade and diagnostic follow-ups

The native updater used to check out a release and run `make build` against whatever was already in `lime/node_modules`. In this checkout that was Next 16.1.7 despite a 16.4.1 lock. The shared `build-ui` target now runs `npm ci` before deleting staging output or compiling. This reaches direct production builds, native installation, and the updater while preserving its build-user privilege and pre-cutover failure order. It needs registry access or a complete npm cache, replaces that checkout's dependencies, and must not share them with an active development server. Existing installed services remain running when dependency installation or the build fails. Docker and CI already install from locks; the existing CI step is redundant but unchanged.

Real-browser verification also exposed a prior hardening regression: navigation was blocked, but whole-message URL redaction removed its actionable policy reason. `safelog.Sprintf` now shares `Printf`'s per-argument sanitization, and Juicer's returned diagnostics use it before appending trusted policy counts. Conservative unstructured URL-tail removal is unchanged. Tests include userinfo, raw whitespace, uppercase and opaque HTTP(S) forms, wrapped causes, counts, and ordinary errors. The first failed browser result is retained separately from the final passing run.
